## Independent panic and watchdog prototype

The prototype is based on the frozen Claude commit. It remains separate from
the normal installation and from this worktree's earlier renderer experiments.

Implemented and tested:

1. A separate **Aeolus Safety Control** window provides **PANIC — SILENCE AUDIO**
   and explicit **Resume audio**, independent of the main application UI.
2. Panic posts an atomic request. Workers check at bounded rendering checkpoints;
   the audio owner waits for all outstanding jobs before reclaiming voices and
   acknowledging. It does not return into buffers that workers are still using.
3. Panic latches silence, including reverb output, and discards notes entered
   while muted. Resume stops/reprepares the audio device outside processing,
   clears old effect history, and retains registration and audio setup.
4. If acknowledgement does not arrive within one second, the independent
   controller sends SIGTERM to the exact owned test process. If it survives
   another three seconds, it sends SIGKILL. PID descriptors guard against PID reuse.
5. A separate watchdog initiates that sequence after five seconds without
   telemetry progress. The receiver, panel and watchdog run on efficiency cores.

Telemetry currently comes from a GUI-timer-flushed callback CSV. A stale file
can mean UI or audio blockage; it does not identify a worker deadlock. Explicit
audio reprepare has a bounded 30-second setup allowance. This remains a controlled
test prototype, not a release-ready general health monitor.

The implementation and reproduction instructions are in
[tools/claude_panic/README.md](tools/claude_panic/README.md).

## Agreed recovery direction

- Reliability comes first: the aim is to eliminate the hang so recovery is
  rarely needed. Do not sacrifice sound quality or silently drop normal notes.
- Final-release recovery should first silence/recover within Aeolus. If that
  fails, terminate and automatically relaunch with saved setup so playing can
  resume quickly. **Automatic application restart is deferred during testing,
  not excluded from the final release.** It is not implemented in this prototype.
- Incorporating controls into the main UI is feasible, but a frozen UI cannot
  accept a click. Retain an independent recovery path.
- A physical VIM4 GPIO panic button is a possible independent input. No GPIO
  implementation or wiring validation has been done; verify the exact board
  pinout and electrical requirements before wiring.
